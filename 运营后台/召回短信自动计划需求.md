# 召回短信自动计划需求

## 目标与范围

运营可以为不同用户群分别创建自动召回计划，例如“流失 3 天召回”和“流失 7 天召回”。计划按设定周期执行，每次执行时重新筛选当时符合条件的用户，向该批用户发短信，并在召回批次列表生成一条记录。本需求仅涉及自动计划及其生成批次的流程；原有手动创建召回批次、计划类型、成本和报表规则沿用现状。

## 自动计划配置

| 配置项 | 规则 |
| --- | --- |
| 计划名称 | 用于识别不同的召回策略。 |
| 计划类型 | 选择现有计划类型。 |
| 召回方式 | 本次自动化场景为短信。 |
| 状态 | 可启用或停用；停用后不按周期执行。 |
| 前置用户筛选条件 | 勾选需要的条件并填写条件值；同一计划内已勾选的条件同时满足。不同用户群分别创建计划。 |
| 执行频率 | 每日执行或每周执行；每周执行需选择星期几。 |
| 执行时间 | 配置计划触发的时间。 |

### 用户筛选条件

筛选条件参照现有推送目标配置：VIP 等级、注册时间、最后登录时间、已登录的时间范围、未登录的时间范围、总充值、总提现、最后充值时间、最后提现时间、代理下级人数、包 ID。未勾选的条件不参与筛选。

- **VIP 等级**使用下拉多选，可在同一个条件中选择多个等级。
- 时间、天数、金额和人数类条件按页面填写起止值；“未登录的时间范围”另填写查询天数。
- 用户群不在创建计划时固定。每次计划触发时，均按该计划当时保存的条件和最新用户数据重新筛选。

## 执行与批次

1. 到达启用计划的执行日和执行时间后，按当前计划条件筛选用户。
2. 针对本次筛选结果执行短信召回，并为**每次执行**生成独立召回批次，便于查看该次触达和后续效果。
3. 自动生成的批次在原召回批次表中展示，`批次来源`标为“自动”；原有批次标为“手动”。列表支持按批次来源筛选。
4. 自动计划列表展示计划名称、筛选条件、执行周期、状态和最近批次；支持编辑、启用和停用。

## 尚待确认的实现口径

自动计划配置界面不包含短信模板或短信内容。正式自动发送前，需要确定每个计划使用哪条现有短信模板，以及模板失效时如何处理。用户筛选、定时任务、实际短信发送和效果回写也需要服务端实现。

## 原型说明

仓库中的 `recall-sms-automation.js` 仅为可交互的静态原型：展示示例数据；“模拟执行”会在浏览器本地生成自动批次，但不筛选真实用户，也不发送短信。浏览器本地修改保存在 `localStorage`，不代表正式后台数据。
